# Перенос истории из других трекеров

В Standard Tracker откройте **Импорт → Перенести из Hearthstone Deck Tracker**
или **Импорт → Перенести из Firestone**. Завершите текущий матч перед переносом.
Проверка покажет новые колоды и матчи, повторы, неподдерживаемые режимы,
некорректные записи и матчи без привязки к колоде. До нажатия «Перенести»
данные профиля не изменяются.

Библиотека Standard Tracker имеет собственные модели и формат
`%APPDATA%\StandardTracker\library.json`. Перенос преобразует чужие данные в
этот формат. После переноса HDT/Firestone и исходные файлы не нужны для
сохранения прогресса. Устройство библиотеки описано в [LIBRARY.md](LIBRARY.md).

## Hearthstone Deck Tracker

1. Закройте HDT, чтобы получить согласованную копию его файлов.
2. Выберите `PlayerDecks.xml` в папке данных HDT, обычно
   `%APPDATA%\HearthstoneDeckTracker`. Для portable-установки выберите папку,
   куда HDT сохраняет данные. Можно использовать заранее сделанную копию.
3. `DeckStats.xml` и `DefaultDeckStats.xml` читаются из этой же папки.
   При отсутствии файла приложение явно сообщает об этом. Если сохранились
   только файлы статистики, можно выбрать их; матчи останутся в общей статистике.

Импорт сохраняет названия, теги, архивное состояние, содержимое колод и их версии.
Одинаковые карты, количества и дополнительные карты сопоставляются с уже
существующей колодой. Её сохранённое название остаётся прежним. Недостающие версии
добавляются с непересекающимися номерами, и история получает соответствующие
номера версий. Учитываются матчи Standard/Wild Ranked/Casual и Friendly.

## Firestone

Поддерживаются JSON с массивом записей GameStat, объект `{ "stats": [...] }`,
объект `{ "matchHistory": [...] }` и Dexie JSON export таблицы `matchHistory`.
В Windows 10+ также можно выбрать `FirestoneDB.sqlite` версии Electron:
приложение читает `matchHistory.data` в режиме read-only.

Для Firestone Overwolf:

1. Откройте инструменты разработчика **окна Firestone**, вкладку Console.
   Доступ к DevTools зависит от установки Overwolf; обычный браузер или консоль
   другого окна не имеет доступа к базе Firestone.
2. В Standard Tracker выберите **Импорт → Выгрузить историю Firestone** и нажмите
   «Скопировать скрипт».
3. Вставьте скрипт в Console Firestone и выполните. Скрипт читает всю таблицу
   `FirestoneDB.matchHistory` через read-only транзакцию. Консольный `copy()`
   помещает JSON в буфер обмена; число записей выводится в консоль.
4. Вставьте JSON в Блокнот, сохраните `firestone-history.json` в UTF-8 и выберите
   этот файл через **Перенести из Firestone**.

Скрипт доступен в исходниках: `Hearthstone Deck Tracker/Importing/FirestoneExport.js`.
Если база или таблица отсутствуют, он останавливается без создания базы.
Если DevTools недоступны, нужен JSON-экспорт таблицы из Firestone; Standard
Tracker не извлекает записи напрямую из внутренних файлов Chromium LevelDB.

Старый `user-match-history.json` тоже читается, но этот кэш устарел и может
не содержать новые матчи. Используйте полную выгрузку таблицы, чтобы перенести
всю доступную локальную историю.

Колоды восстанавливаются из `playerDecklist`. Матчи без кода или с непрочитанным
кодом сохраняются в общей статистике с классом и исходным названием. Firestone
экспортирует историю, поэтому колоды, которыми ещё не сыграно ни одного матча,
надо добавить отдельно по коду. Дата окончания берётся из `creationTimestamp`,
дата начала вычисляется по `gameDurationSeconds`. Сохраняются результат,
противник, имена, монетка, ходы, режим, формат, регион и ранг.

## Повторы, резервные копии и ограничения

Повторный импорт одного источника не добавляет уже перенесённые матчи:
HDT проверяется по GameId, Firestone по reviewId и стабильному локальному ID.
Записи без идентификатора получают ID из содержимого. Совпадение одного и того
же матча в двух разных трекерах с разными идентификаторами автоматически
не определяется: импортируйте единственную полную историю для периода пересечения.

Перед записью наша `library.json` сохраняется в
`%APPDATA%\StandardTracker\ImportBackups\<дата-идентификатор>`. Сохранение готовит
временный файл и атомарно заменяет библиотеку целиком; обычная ошибка замены
оставляет прежний файл. При аварийном завершении процесса резервная копия
остаётся доступной. `files-before.txt` указывает, существовала ли библиотека
до импорта. Для ручного восстановления закройте трекер и верните `library.json`
из этой копии в его папку данных. Если это был первый импорт в пустой профиль,
для возврата к пустому профилю удалите `library.json` и его `.bak`.

Чужие настройки, коллекция карт и файлы повторов не переносятся. История
не получает ссылки на чужую папку повторов. Пропуски неподдерживаемых режимов
(например Battlegrounds, Arena, Twist) и повреждённых матчей отображаются
отдельными числами. Исходные файлы другого трекера не изменяются.

## Проверенные исходные форматы

Схема проверена 2026-10-01 по первичным исходникам:

- [Firestone GameStat](https://github.com/Zero-to-Heroes/firestone/blob/master/libs/stats/data-access/src/lib/models/game-stat.ts)
- [Firestone загрузка и хранение истории](https://github.com/Zero-to-Heroes/firestone/blob/master/libs/stats/data-access/src/lib/services/game-stats-loader.service.ts)
- [Firestone IndexedDB](https://github.com/Zero-to-Heroes/firestone/blob/master/libs/shared/framework/core/src/lib/services/indexeddb.service.ts)
- [Firestone SQLite](https://github.com/Zero-to-Heroes/firestone/blob/master/apps/electron-app/src/app/services/sqlite-database.service.ts)
- [Firestone построение даты матча](https://github.com/Zero-to-Heroes/firestone/blob/master/libs/stats/services/src/lib/services/game-stat-builder.ts)

XML HDT читается адаптером `HdtProfileReader`; сериализация нашей библиотеки
задаётся отдельным проектом `StandardTracker.Library`. Профиль исходного HDT
автоматически не подключается. Перенос из другого трекера выполняется только
выбранным пользователем действием.
