## Назначение и поведение

Плагин передаёт завершённые матчи на **HSGuru**, используя адрес `https://www.hsguru.com`. Старое название d0nkey.top осталось в имени DLL, свойствах и журналировании.

[Страница автора](https://www.hsguru.com/hdt-plugin) описывает вклад в общую статистику Decks, персональные My Decks/My Replays и Streamer Decks. Это серверные функции сайта; плагин сам не строит оверлей статистики, не выбирает лучшие ходы, не загружает винрейты или рекомендации муллигана.

Последовательность в проверенном коде:

1. `OnLoad()` запускает проверку обновления и регистрирует `GameEnd` в `GameEvents.OnGameEnd`.
2. Завершение игры вызывает создание `DTGame` из `API.Core.Game`, сериализацию в JSON и HTTP **PUT** на `/api/dt/game?source=hdt_plugin`.
3. Сразу отправляется пакет с текущим `ReplayUrl`, включая случай его отсутствия.
4. Через 10 секунд начинается поиск ссылки на реплей HSReplay. При отсутствии ссылки проверка повторяется каждые 5 секунд; ожидание заканчивается примерно через 165 секунд от окончания игры. При появлении ссылки заново собирается и отправляется пакет.
5. `OnButtonPress()` повторяет проверку обновления. `OnUpdate()`, `GameStart()`, `TurnStart()` и `OnUnload()` пустые; начало игры и начало хода здесь не подписаны на события.
6. Обновление использует GET `/hdt-plugin/latest-version` и, при более новой версии, `/hdt-plugin/latest`. Загрузка записывается по пути `Config.AppDataPath/Plugins/d0nkey.top plugin.dll`; применение предполагает перезапуск HDT.

Новый HTTP-клиент создаётся внутри DLL. Общий `OfflineHttpHandler` нашего приложения такой клиент не блокирует: включение DLL фактически разрешит её собственные сетевые запросы.

## Какие данные уходят

Сериализуемые `DTGame`, `DTPlayer` и `DTCard` содержат:

- идентификатор матча, результат, режим, формат, регион, время начала/окончания, длительность в целых минутах, число ходов, сезон, сборку игры;
- героев, классы, имена обоих игроков; `DTPlayer.Battletag` берётся из `Player.Name`, который в нашем проекте может содержать полный BattleTag;
- ранги/легендарные места, звёзды и их изменения, множитель звёзд, признаки Монетки, внутренние ID участников/сценария, рубашки; также поля рейтингов Battlegrounds/Mercenaries, даже если режим нашей сборкой не поддерживается;
- код собственной колоды, в основном пути включая сайдборды; полная колода соперника не извлекается, его `Deckcode` передаётся как null;
- сыгранные карты обоих участников, ID сущности, ход и определённый источник создания;
- предполагаемые карты из первоначальной колоды по информации сущностей и ходам; свои карты до муллигана и стартовую руку с отметкой сохранения;
- карты с эффектами начала игры и сведения о сущностях из `game.Entities`;
- ссылку на HSReplay, если она уже доступна.

Это использует информацию, уже доступную трекеру. DLL не добавляет способ раскрывать неизвестную руку или полную скрытую колоду соперника. Пароли и токены Battle.net в исследованных моделях пакета отсутствуют; имена и BattleTag при этом передаются.

## Подтверждённые ограничения кода

1. **Нет Death Knight в `DTGame.Hero(string)`**. Неизвестный класс получает фиксированный запасной HeroDbfId `42458`. Путь через активную локальную колоду поэтому может сериализовать DK с неправильным героем.
2. **Повторная отправка держит изменяемый `GameV2`**, а не снимок закончившегося матча. Наш `Core.Game` сохраняется, но `CurrentGameStats` и сущности заменяются при следующей игре. Отложенная работа способна прочитать другую игру или очищенное состояние.
3. **`OnUnload` не отменяет уже запущенные задачи**. Обёртка штатного HDT может убрать отключённый обработчик при следующем событии; это не отменяет отложенные отправки. Простое ручное создание `Plugin` без регистрации в PluginManager также лишает его этой привязки к состоянию обёртки.
4. **Пустой `createdBy` трактуется как исходная карта** в списке `cards`. Неопределённый источник нельзя автоматически считать доказательством происхождения из первоначальной колоды.
5. **История использует изменяемые сущности `CardsPlayedThisMatch`**. В нашем проекте у этого списка уже известны пропуски специальных путей и ограничения повторных розыгрышей; плагин их не устраняет.
6. **Муллиган читается через приватное `_mulliganState` и reflection**. При отсутствии снимков применяются приблизительные восстановления, в одном из которых `Distinct()` теряет одинаковые экземпляры карт. Прямой публичный интерфейс снимков надёжнее для нашего кода.
7. **Нет долговременной очереди для сетевых ошибок**. Лог «Sent game» пишется и при неуспешном HTTP-статусе; статус записывается дальше, но не используется для подтверждения успешной доставки.
8. **Обновление записывает DLL через `FileMode.Open`**, без атомарной замены и усечения более длинного старого файла. В коде загрузки нет проверки подписи или хеша нового содержимого.

## Состояние нашего проекта

- `Hearthstone Deck Tracker/Plugins/PluginManager.cs`: `LoadPluginsFromPath` и `LoadPlugins` оставлены пустыми.
- `Hearthstone Deck Tracker/Core.cs`: вызовы загрузки плагинов, их UI и обновлений при старте отключены.
- `Config.HsReplayAutoUpload` и `GameEventHandler.UploadCurrentGameMode` возвращают false; HSReplay API-загрузка отключена. Первичная отправка плагина не требует ссылки, но её отложенное ожидание в нашей сборке бесполезно.
- `API/GameEvents.cs` и событие окончания матча сохранены. `GameEventHandler` заполняет состав колоды и результат, вызывает `GameStats.GameEnd()`, затем `GameEvents.OnGameEnd.Execute()`.
- `GameV2` содержит приватные снимки муллигана; `MulliganState` хранит OfferedCards, KeptCards, FinalCardsInHand.
- `Hearthstone/HearthDbConverter.cs` уже содержит преобразование колоды в HearthDb с выбором героя из базы. В собственном модуле не нужен ручной список десяти классов из DLL.
- Поддерживаются Standard/Wild Ranked, Casual, Friendly через `StandardMode.IsSupported`; проверку допустимых для внешней статистики режимов нужно делать отдельно. Нельзя автоматически отправлять дружеские/незавершённые игры в статистику рейтинга.

## Рекомендуемый путь

Создать собственную необязательную интеграцию HSGuru поверх существующего события окончания матча и данных трекера. Общий механизм загрузки сторонних DLL для этого не требуется.

1. **Локальный снимок матча.** Снять неизменяемые данные после завершения игры: GameId, результат, подтверждённый формат/режим, колода с сайдбордами, известные карты, снимки муллигана. Для полноценной истории розыгрышей сохранять события в момент успешного розыгрыша с учётом отмены, повторов и неизвестного источника.
2. **Отдельная настройка отправки.** По умолчанию выключена. Интерфейс должен прямо говорить о передаче колоды, результатов и имён/BattleTag. Не добавлять новые согласия в обычные локальные сценарии; настройка нужна только для выбора внешней интеграции.
3. **Отдельный клиент HSGuru.** Использовать собственный HttpClient с тайм-аутом, очередь, ограниченные повторы, подтверждение HTTP-успеха, идентификатор матча для повторов и отмену задач при отключении. Сохранить локальную запись независимо от доступности сайта. ReplayUrl оставить необязательным, HSReplay ради этой функции не возвращать.
4. **Верный формат данных.** Собрать JSON по контракту HSGuru, исправить классы/сайдборды/семантику карт. Для собственного клиента согласовать обозначение Source/SourceVersion и контракт с автором, вместо выдачи его за неизменённую версию HDT-плагина.
5. **Результат для пользователя.** Добавить статус доставки и ссылки на историю/колоду на сайте. Серверный ответ может содержать `player_deck`, `player_archetype`, `opponent_archetype`; полученный архетип можно предложить для нашей библиотеки, сохраняя приоритет ручного значения.

Для исследования можно временно восстановить загрузку одной конкретной DLL через штатную обёртку, но это отдельный эксперимент с сетью, старой бинарной зависимостью и описанными дефектами. Простое копирование в Plugins в текущем проекте не работает.

## Получение информации с сайта — отдельная функция

Дополнение 2026-10-01: GET `/api/deck-info/{deckcode}` проверен на живом сервере и вернул HTTP 200 с JSON на `www.hsguru.com` и `api.hsguru.com`; неверный код вернул HTTP 400. Подробное исследование доступа к винрейтам, матчапам и муллигану: [HSGuru statistics API](hsguru-statistics-api.md).

[README автора](https://github.com/borisbabic/d0nkey.top#api) документирует GET `/api/deck-info/$DECKCODE`, возвращающий `archetype`, `name`, канонический `deckcode`. Это может помочь автоматически определять архетип в нашей библиотеке без отправки матчей: отправляется только запрошенный код колоды.

Этот ответ не содержит винрейта, статистики матчапов или рекомендаций муллигана. Для таких функций потребуется отдельно исследовать доступный API и его условия; они не появляются от установки найденной DLL.

## Что проверено и что остаётся проверить при реализации

Статически подтверждены файл/версия/хеш, отправляемая модель, сетевые адреса, жизненный цикл, перечисленные дефекты и точки подключения нашего кода. Через чтение [серверного контроллера](https://github.com/borisbabic/d0nkey.top/blob/master/lib/backend_web/controllers/deck_tracker_controller.ex) и [маршрутов](https://github.com/borisbabic/d0nkey.top/blob/master/lib/backend_web/router.ex) подтверждены PUT/POST `/api/dt/game`, обработка идентификатора и поля ответа.

Работа живого API и принятие матчей не проверены. Запрос версии на HSGuru из исследовательской среды получил HTTP 403; это не доказывает отказ API для обычного трекера. Не выполнялись запуск DLL, сетевые PUT с матчами или тест в Hearthstone.

Для будущей реализации нужны проверки на локальном HTTP-сервере: DK и остальные классы, сайдборды, обе поддерживаемые формы матчей, отключённая отправка, сбои сети, повтор одного GameId, начало следующего матча во время очереди, выключение интеграции, пустые снимки муллигана и неизвестные источники карт. Затем — один явно разрешённый реальный матч с подтверждением записи на стороне HSGuru.

Исходники отдельного проекта плагина из пути в PDB (`borisbabic/d0nkey.top-hdt-plugin`) по публичному адресу возвращают 404. В публичном репозитории сайта лежит бинарник; LICENSE сайта имеет заголовок AGPLv3. Включение декомпилированного кода в распространяемое приложение потребует отдельного уточнения лицензии именно плагина. Рекомендация выше относится к собственной реализации протокола, а не к копированию декомпилированных классов.
