# HSGuru: получение информации и статистики — 2026-10-01

Задача: выяснить, можно ли получать данные HSGuru и показывать их внутри Standard Tracker. Исследование выполнено без отправки матчей, личных данных, сообщений автору и без изменения кода приложения.

## Короткий результат

**Получение архетипа работает через публичный JSON API и проверено живым запросом.** Для винрейтов, меты, матчапов и муллигана публичный документированный JSON API в исследованных документах и маршрутах не обнаружен. Эти данные существуют на сайте и рассчитываются серверными модулями, но это не доказательство доступного внешнего API.

Проверенная версия исходников сайта: commit `13d54ecff5e9990eeadde763bda60b01ba01a136` в [borisbabic/d0nkey.top](https://github.com/borisbabic/d0nkey.top/tree/13d54ecff5e9990eeadde763bda60b01ba01a136).

## Живые запросы

GET `/api/deck-info/{deckcode}` с примером Even Shaman из README:

- `https://www.hsguru.com` — HTTP 200, `application/json; charset=utf-8`.
- `https://api.hsguru.com` — HTTP 200, такой же ответ.
- Ключ/API-токен и вход не использовались.

Фактический ответ:

```json
{
  "name": "Even Shaman",
  "archetype": "Even Shaman",
  "deckcode": "AAEBAaoIAs30Aob6Aw6VAZQDvgbSE/bwAp79Ar2FA7SXA9qlA/DUA6reA9b1A/q0BPTQBQAA"
}
```

Входной пример — историческая Wild-колода, а не рекомендация для актуальной меты. Входной код:

```text
AAEBAaoIAs30Aob6Aw6VAZQDvgae/QK9hQO0lwPapQPw1AOq3gPW9QP6tAT00AXAngbmngYA
```

Неверный код: GET `https://www.hsguru.com/api/deck-info/not-a-deck-code` — HTTP 400, `Invalid deck. Could not decode id`.

GET `/meta` на обоих указанных хостах вернул HTTP 403 и страницу Cloudflare `Just a moment...`. Это результат исследовательского HTTP-клиента; не утверждение, что страница недоступна пользователю в обычном браузере. Проверки защиты не обходились.

## Что реально предоставляет документированный API

[README API](https://github.com/borisbabic/d0nkey.top#api) описывает `archetype`, `name`, канонический `deckcode`. Обработка находится в [DeckController](https://github.com/borisbabic/d0nkey.top/blob/13d54ecff5e9990eeadde763bda60b01ba01a136/lib/backend_web/controllers/deck_controller.ex).

- GET `/api/deck-info/{deckcode}`: определение архетипа и нормализация кода колоды.
- POST `/api/deck-info`: пакетный запрос колод; в README есть оговорка о его низком приоритете и возможной неработоспособности. В этом исследовании пакетный метод не проверялся, поэтому первую реализацию нужно строить на подтверждённом GET.
- `/api/cards/collectible`, `/api/cards/metadata`, `/api/cards/dust-free`: сведения о картах; это не винрейты, не матчапы и не советы муллигана.
- PUT/POST `/api/dt/game`: загрузка своего матча. Отправка матча не выдаёт общий набор статистики в ответ. См. [разбор DLL](d0nkey-plugin-audit.md).

Неопределённый архетип может быть null. Ответ описывает классификацию колоды, а не вероятность её победы. Код колоды передаётся серверу, но запрос не требует передачи BattleTag, истории игр или коллекции.

## Где находится большая статистика

[Router](https://github.com/borisbabic/d0nkey.top/blob/13d54ecff5e9990eeadde763bda60b01ba01a136/lib/backend_web/router.ex) отделяет JSON `/api/deck-info` от страниц Phoenix LiveView `/meta`, `/deck/*deck`, `/matchups`, `/card-stats`, `/archetype/:archetype`.

| Данные | Где реализованы | Состояние внешнего доступа |
| --- | --- | --- |
| Архетип/название колоды | DeckController `/api/deck-info` | JSON GET подтверждён |
| Винрейт и популярность архетипов, средние ходы/длительность, скорость подъёма | MetaLive → TierList → DeckTracker.archetype_stats | На сайте; документированный JSON endpoint не найден |
| Винрейт конкретной сборки и результаты против классов | DeckLive → OpponentStatsTable → DeckTracker.detailed_stats | На сайте; документированный JSON endpoint не найден |
| Матрица матчапов архетипов и размеры выборок | MatchupsLive → MatchupsExplorer → DeckTracker.matchups | На сайте; документированный JSON endpoint не найден |
| Mulligan/Kept/Drawn Impact и число наблюдений | CardStatsLive → DeckTracker.card_stats → CardStatsTable | На сайте; документированный JSON endpoint не найден |

Исследованные модули получают данные из PostgreSQL через Ecto/Repo, а не из общего внешнего JSON endpoint, к которому можно просто подключить трекер. Phoenix LiveView — способ отображения и обновления страниц; наличие сообщений веб-сокета не превращает его во внешний поддерживаемый статистический контракт.

В коде есть готовые агрегаты и расчёты по исходным матчам. Доступность зависит от сочетания формата, периода, ранга и остальных фильтров. MetaLive и OpponentStatsTable требуют входа для некоторых неагрегированных запросов. Наличие переменной `premium` само по себе не означает, что любые такие данные доступны только по платной подписке; конкретные проверки различаются.

В [пояснении статистики](https://github.com/borisbabic/d0nkey.top/blob/13d54ecff5e9990eeadde763bda60b01ba01a136/lib/backend_web/controllers/stats_html/explanation.html.heex) автор отмечает нагрузку неагрегированных запросов. Для массовой интеграции логично получать готовые агрегированные срезы, а не инициировать новые тяжёлые расчёты при каждом действии пользователя.

Открытый исходный код не содержит производственную базу матчей. Развёртывание своего экземпляра сайта само по себе не даёт накопленную статистику HSGuru.

## Реалистичные способы интеграции

### 1. Доступные функции первого этапа

- При импорте/выборе колоды обращаться к проверенному GET и предлагать архетип.
- Хранить полученный архетип отдельно от ручного значения или заполнять только пустое поле. В `Hearthstone/Deck.cs` уже есть сохраняемое свойство `Archetype`.
- Не заменять локальное название и состав колоды автоматически на серверный вариант. Канонический код полезен для сопоставления, но пользовательское название остаётся локальным.
- Давать ссылку на страницу нужной колоды, её карточной статистики и архетипа, сохраняя формат/период/ранг там, где маршруты сайта это поддерживают.
- Кешировать ответы по составу колоды, выполнять запросы в фоне, при сетевой ошибке использовать сохранённые сведения.

В нашей сборке общий HTTP-клиент намеренно отключён. Для этой возможности понадобится отдельный клиент с доступом к HSGuru и явной настройкой онлайн-функции; основная локальная работа не должна зависеть от неё.

### 2. Полноценная статистика внутри трекера

Предпочтителен подтверждённый автором API/экспорт готовых агрегатов. Минимально полезный набор: статистика конкретной сборки; статистика архетипа; матчапы; карточные метрики; перечни доступных рангов/периодов; время обновления и размеры выборок.

Схема будущей интеграции: HSGuru → клиент данных → локальный кеш → нормализованные модели статистики → библиотека колод/панель муллигана. Публичные интерфейсы нужны до реализации отображения настоящих чисел.

В [похожем запросе другого проекта](https://github.com/borisbabic/d0nkey.top/issues/189#issuecomment-5793308549) автор 2026-09-23 написал, что не заинтересован в сотрудничестве. Это конкретный ответ другому заявителю и не устанавливает общий запрет на документированный API, но обещать нам партнёрский доступ на его основании нельзя. Автору от нашего имени никто не писал.

### 3. Парсинг веб-страниц

Технически является отдельной стратегией, а не использованием документированного JSON API. В исследованной среде прямое чтение страницы меты остановилось на HTTP 403, поэтому надёжный автоматический источник для её статистики здесь не подтверждён.

Даже при обычном доступе нужно учитывать изменение разметки, загрузку через LiveView, авторизацию, фильтры и неполные таблицы. Строить основной продукт на таком способе без рабочего подтверждения и условий внешнего использования не стоит. Интеграция должна сообщать об отсутствии/устаревании данных, а не подставлять нули.

## Что могло бы появиться в нашем интерфейсе после получения статистического доступа

- В библиотеке: общий винрейт, число игр и популярность для своей точной сборки либо отдельно обозначенного архетипа.
- В истории: сравнение своей статистики с общим срезом при сопоставимых рангах, формате и периоде.
- В деталях колоды: результаты против классов/архетипов и несколько популярных вариантов сборки.
- В муллигане: доступные метрики карт с числом наблюдений и учётом класса противника/Монетки там, где источник поддерживает такой срез.
- При раскрытии карт соперника: можно проектировать собственную оценку вероятного архетипа, но проверенный `/api/deck-info` не предоставляет классификацию по частичному набору карт. Полная колода соперника не становится известной через этот API.

## Как избежать неверных выводов

1. Точная колода и архетип — разные уровни данных; замена одной карты может изменить статистическую выборку.
2. Всегда хранить формат, период/патч, ранг, источник, число игр, время обновления и применённые фильтры вместе с метрикой. Если каких-то сведений источник не дал, не выдумывать их.
3. Общая база из миллионов матчей не означает большую выборку для одной сборки, карты или конкретного матчапа.
4. Mulligan Impact описан как разность винрейта игр с картой после муллигана и общего винрейта колоды; учитываются и оставленные карты, и полученные заменой. Kept Impact относится к оставленным картам. Это разные показатели.
5. Пример, не реальные цифры HSGuru: колода выигрывает 52%, с картой после муллигана — 61%; impact равен +9 процентным пунктам. Из этого не следует, что сохранение карты причинно увеличивает шанс победы ровно на 9 пунктов.
6. Просроченные цифры показывать с датой, отсутствующие — как отсутствие данных, а не 0%.
7. В пояснении автора Deck Stats относятся к точному списку карт с сайдбордами, а Meta Stats отражают перспективу пользователей трекера. Это выборка участников источника, а не гарантированно всех игроков Hearthstone.
8. Матрица Matchups использует отдельную классификацию по сыгранным картам, поскольку полная колода противника неизвестна. После патчей и выпуска новых карт эта классификация требует обновления и накопления данных. Её значения не следует автоматически приравнивать к статистике двух полностью известных списков колод.

## Рекомендуемый порядок

Сначала реализовать проверенный GET, кеш, предложение архетипа и переходы к статистике. Получение агрегатов для винрейтов/матчапов/муллигана держать отдельным следующим этапом до подтверждения подходящего источника. Передача матчей через DLL — самостоятельная функция и не является обязательным условием для текущего GET.
